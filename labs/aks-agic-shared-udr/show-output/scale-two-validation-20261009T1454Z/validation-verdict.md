# Offline scale-out evidence review

**Verdict: PASS for the captured scale-out, AGIC configuration write, and backend-health checks.** This is a review of retained captures only, not a live Azure check or a claim about the lab's current state. All times below are UTC on 2026-10-09 unless stated otherwise.

## Evidence supporting the scoped pass

- The mutation capture recorded `kubectl scale deployment web --replicas=2` exiting 0 at 14:40:55–14:40:56, followed by a successful rollout at 14:40:56–14:40:58. The new pod `10.244.0.18` appeared alongside `10.244.0.14` in the successful pod and endpoint snapshots at 14:40:58–14:41:01.
- AGIC logs in the later validation capture contain `BEGIN AppGateway deployment` at 14:40:59.465774, `Applied generated Application Gateway configuration` at 14:41:09.253017, and `END AppGateway deployment` at 14:41:09.253701. The apply event was about 14 seconds after the scale command began. This is direct evidence of an AGIC configuration write after scale, not proof that every controller or gateway control-plane function was validated.
- The Application Gateway pool output captured at 14:42:38.546–14:42:47.144 contains both backend IPs. Thus the second IP was present no later than about 112 seconds after scale. This is the first valid captured pool observation, not the exact time the address was added; the pre-scale pool query failed, so a pool-before/pool-after differential was not captured. These supplemental text captures retain start/end times and output but not an explicit process exit code.
- Successful deployment, pod, EndpointSlice, Application Gateway state, pool, and backend-health commands in the validation capture report two desired/ready/available replicas, both IPs in the EndpointSlice and pool, and both IPs Healthy for public and private HTTP settings. The backend-health query exited 0. Its capture completed at 14:56:58, so that check was about 16 minutes after scale.
- The post-scale route-table output captured at 14:41:28–14:41:35 is valid JSON with the five expected routes, including both `/1` NVA routes, `GatewayManager → Internet`, default `→ Internet`, and the kubenet node route. The supplemental capture does not preserve an explicit process exit code. No pre-scale route snapshot exists; this does **not** prove that routes were unchanged.

## Inconclusive checks and timing caveats

- The two post-scale pod egress commands did not test application egress: both failed with exit 1 because the AKS API hostname did not resolve, preventing `kubectl exec`. The validation route query also failed/timed out. Therefore this run does not revalidate egress from either pod or establish a fresh route differential. An earlier, separately dated gateway-manager validation observed NVA egress from one pod; it is not evidence of post-scale egress from both pods.
- The validation runner began at 14:56:25 on Oct 9, but its route query started at 14:57:01 and did not finish until 05:09:11 on Oct 10. Subsequent route-association and pod-exec records are dated Oct 10; both exec attempts failed. The aggregate summary consequently ends at 05:09:54 Oct 10. Do not treat the whole summary as a contemporaneous snapshot or infer a successful full validation suite from it.
- The mutation helper's pre-scale Application Gateway listing/pool lookup did not yield a gateway name; two intervening pool attempts queried an invalid name. The separately captured successful pool snapshot is the valid post-scale observation. The retained `summary.json` and earlier generated `verdict.json` used an unsupported 190-second interval; the corrected `../scale-two-mutation-20261009T1439Z/verdict.json` reports the raw capture times and 112-second upper bound instead.
- Both workload pods were on the same node. This does not exercise cross-node pod routing or prove that an AKS node/pod CIDR route changed or remained unchanged.
- The historical desired replica count of two in these captures is not the repository's initial sample configuration (`deploy/k8s/sample.yaml` remains at one replica) and is not a verified Oct 12 live setting. No Azure calls were made for this review; current resource existence, configuration, and cost are unknown.

The JSON/text captures alongside this report contain the individual commands, exit codes, and per-command timestamps. Local user paths, generated node/pod identifiers, AKS API hostname, and GUIDs were redacted; addresses and relevant role/route values were retained.
