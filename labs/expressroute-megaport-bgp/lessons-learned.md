# expressroute-megaport-bgp — lessons learned

- **Megaport market pivot is valid when evidence is present.** The manifest preferred Madrid, but the deployed MCR is in Equinix Frankfurt FR5 (`locationId=131`). Azure still learned the MCR prefixes, so co-location with the ER peering location is not required for this lab. Evidence: `show-output/15-megaport-mcr.txt`, `10-er-gateway-learned-routes.txt`.
- **Megaport read API shape differs from the skill examples.** GET `/v2/product/vxc/{uid}` and `/v2/product/mcr2/{uid}` returned unsupported/no-endpoint responses, while generic GET `/v2/product/{uid}` returned full product JSON. Evidence: `15a-*`, `16a-*`, `17a-*`, and `15`/`16`/`17`.
- **VLAN observation: both VXCs are VLAN 100.** The primary and secondary VXC resources both show `b_vlan`, `a_vlan`, and peer `vlan` as `100`. This confirms Tank's report; unusual, but the VXCs are `LIVE`/`up` and Azure learned the routes. Evidence: `16-megaport-vxc-primary.txt`, `17-megaport-vxc-secondary.txt`.
- **ER circuit route-table command anomaly.** Circuit ARP tables show both MCR/Microsoft peer IPs, and the ER gateway learns routes, but `az network express-route list-route-tables` and `list-route-tables-summary` both return `Gateway does not have any Bgp sessions.` Evidence: `04`, `05`, `04a`, `05a`, `06`, `07`, `10`.
- **MCR looking glass was not usable in this API session.** The documented `/diagnostics/routes/bgp` path returned no endpoint, not an empty route array. VXC resources plus Azure gateway/NIC route evidence are the fallback. Evidence: `18-megaport-mcr-looking-glass-bgp-routes.txt`, `16`, `17`, `10`, `13`.
- **VM lifecycle drift can block late diagnostics.** `az vm run-command` succeeded for `ip route`, but the VM was deallocated before ping and effective NSG capture. No start operation was attempted because Niobe is read-only. Evidence: `19-vm-ip-route.txt`, `20-vm-ping-connectivity.txt`, `22-vm-instance-view-after-ping-blocked.txt`.
- **ER gateway live output should override HCL assumptions.** The live gateway is `gatewayType: ExpressRoute`, SKU `Standard`, `provisioningState: Succeeded`, and `vpnGatewayGeneration: None`; keep Terraform/AVM gateway settings explicit and validate from deployed output. Evidence: `08-er-gateway-show.txt`.
